# 属性 / 数值设计原则

> Percussion L0 基础属性的设计原则与最终清单（7 维）。

---

## 1. 核心框架：两类属性派生

**关键洞察**：派生作用按"对手是谁"分两类，设计规则完全不同。

| 类别 | 对手 | 规则 | 例子 |
|---|---|---|---|
| **对抗性派生** | 同型数值（**跨角色**或**自身内部需求**） | **线性永久无封顶**（双方同步膨胀） | 物伤 ↔ HP/物抗；命中 ↔ 闪避；MP 上限 ↔ 法术耗蓝；体力上限 ↔ 行动耗费 |
| **非对抗性派生** | 物理 / 心理 / 系统约束 | **递减但永不硬封顶**（log 或渐近曲线） | 移速、攻速、视野（软上限）；暴击率、CDR（硬上限） |

→ **对抗 ≠ 必须跨角色**。资源池（MP / 体力）的对手是"自身释放强法术 / 强招式所需消耗的资源"。后期招式威力↑ → 消耗↑ → 资源池上限必须↑，这是**自身内部对抗**，同样线性永久无封顶。
→ 数值膨胀的本体是**对抗性派生**。挂机游戏从 1 级到 100 级，双方数字一起涨 10 倍，相对关系不变，体验一致。
→ 非对抗性派生**硬封顶 = 反 idle**（告诉玩家"够了别投了"= D2 力量陷阱）。正确做法按上限类型选曲线：
  - **软上限**（移速、攻速、视野——无明确数值，靠感知 / 可玩性约束）→ **log 增长**，永不触及"看不过来"区间
  - **硬上限**（暴击率 100%、CDR 0 秒——数学定义）→ **渐近曲线**：`1 - e^(-x/k)` 或 `base / (1 + k·X)`，无限逼近永不触及

## 2. D2 反面教材

D2 不是因为 4 维太少，是**4 个属性的曲线类型不一致**：力量 / 敏捷是**门槛属性**（够穿装即可）、体力是**鸡肋**、活力是**唯一线性永久**。→ 必然塌成"力敏穿装 + 全堆活力"。挂机游戏特别要避，因为核心快感就是"每点投入都看得见回报"。

## 3. 八条原则

**原则 1**：派生按类分别处理——对抗性 → 线性永久无封顶；非对抗性 → 递减但**永不硬封顶**（log / 渐近曲线）。禁止门槛 / 硬封顶。

**原则 2**：所有属性的边际收益**曲线形状一致**——每点都贡献"百分比池子"，不是"绝对量"。避免 STR `+1 伤害/点` 而 CON `+10 HP/点` 这种隐性权重悬殊。

**原则 3**：没有"通用最优解"。每维都有别维不能替代的事，**强迫取舍**。判断标准：如果"加 X"对所有 build（包括反面 build）都明显有益，违反本条——这种"必加属性"应该走装备词缀承担（提供差异化分配机会）而非 L0。

**原则 4**：每维 **1-2 件事**，事项之间必须同轴（如"命中 + 闪避"= 同一精度轴的两面）。禁止 D2 式"敏捷管命中/格挡/亚马逊伤害"的多职责设计——多职责导致 N² 调参噩梦 + 玩家不知为何加点。

**原则 5**：属性之间显式安排**克制 / 协同**网络。独立 → build 按属性分类（种类有限）；挂钩 → build 按组合分类（种类爆炸）。"自然发生"= 没发生。

**原则 6**：每维必须以**对抗性派生为主战场**（至少 1 条），**非对抗性派生只作调味**（0-2 条）。对抗对手可以是跨角色，也可以是自身资源消耗（见 §1）。

**原则 7**：不分职业。所有 L0 属性对所有玩家等效。职业身份完全由"可学的技能池 + 熟练度"承担，**不污染基础属性系统**——保证养成自由度与跨 build 公平性。

**原则 8**：**等级是玩家强度的体现，不能成为玩家强度的来源。** 等级只承担"给点 / 解锁分配 / 表达成长阶段"的职责，不直接提供增伤、减伤、命中、控制抗性等战斗派生，也不能演化成"推荐等级 / 等级压制 / 等级匹配关卡"这类内容门槛。玩家强弱必须始终由 L0 / 熟练度 / 词缀显式给出，而不是由等级差偷偷决定。

## 4. L0 属性清单（7 维）

| L0 | 单一职责 | 派生 | 对抗对手 |
|---|---|---|---|
| **力量** | 物理伤害乘子 | 物伤 +% | 跨角色：敌人 HP / 物抗 |
| **精神** | 法术伤害乘子 | 法伤 +%（元素细分 → 熟练度 + 词缀） | 跨角色：敌人 HP / 魔抗 |
| **生命** | HP 上限 | HP 上限 +% | 跨角色：敌人输出 |
| **法力** | MP 上限 | MP 上限 +% | **自身内部**：法术耗蓝 |
| **专注** | 行动精度 | 命中率 + 闪避率（同一对抗轴两面） | 跨角色：敌人专注 |
| **意志** | 控制抗性 | 控制时长 / 控制概率 / 控制强度削减 | 跨角色：敌人控制熟练度 |
| **体力** | 行动资源池（耐力条，攻击/格挡/闪避消耗，自动回复） | 体力上限 +% | **自身内部**：武器重量 / 招式耗费 |

### 4.1 全局调参约束：自身内部对抗的同步膨胀

法术耗蓝 / 行动耗费必须**随"威力轴"同速增长**——
- 长得太快 → 加 MP 跟不上耗费 → MP 加点废了
- 长得太慢 → 早期 MP 就够用一辈子 → 加点废了（D2 力量陷阱）

→ 这是全局调参强约束，不能各技能独立设计耗蓝公式。

### 4.2 明确**不进 L0** 的项目

走熟练度 + 装备词缀承担：

| 项目 | 原因 |
|---|---|
| 物理防御 / 魔法防御 | 受击只看 HP；防御纯词缀（避免"必加" + 词缀差异化） |
| 暴击率 / 暴击伤害 | 走装备词缀 |
| 攻速 / CD 缩减 | 走熟练度 + 词缀（避免"必加属性"陷阱） |
| 控制技能的施加参数（时长 / 强度 / 概率） | 走技能熟练度 + 词缀；被控侧抗性由意志承担 |
| AOE 范围 / 持续时间 / 治疗强度 | 走熟练度（每技能各自） |
| 移动速度 | 走装备词缀 |
| HP / MP 回复 | 走药 + 装备词缀 |

→ 上述都是若进 L0 必然成为"任何 build 必加" 的项目，违反原则 3。

### 4.3 召唤物 = 玩家延伸臂膀

召唤物**强度** = 玩家 L0 × 召唤技能熟练度 × 召唤物装备词缀。
→ 召唤流派的加点策略 = 加精神/力量（看召唤物攻击类型），跟法师 build 完全一样。
→ L0 不需要"召唤强度"维度，避免维度膨胀。

**不引入 reservation/spirit 机制**：reservation 假设"上限有界"，与 idle 无限成长的核心哲学冲突——若 reservation 跟着 L0 涨，等于没限制；若不涨，召唤物变强后"召更多"会失控。

**召唤物数量限制**（人为限制）：按熟练度 **log 增长**——非对抗性派生，符合 §1 规则。
- 形如 `count = floor(k · log10(prof + 1)) + 1`
- 早期数量爬升明显（前几只是阶段性成就），后期数量增长极慢，所有成长压力转到强度上
- 与法师"火球更强"（无限）vs"火球放更多次"（受 MP 限制）对称——召唤流派"召唤物更强"（无限）vs"召更多只"（log 软上限）
- 装备 +技能等级直接抬熟练度 → 同时影响数量与强度，永不过时

### 4.4 体力 vs 攻速：正交

- **攻速**（词缀）：每次行动**之间的间隔**变短 → 持续 DPS 上限
- **体力**（L0）：能**连续行动**的次数 → 短时爆发能力

→ 高攻速低体力 = 持续输出型；低攻速高体力 = 爆发型。两个维度互补不重叠。

## 5. 调节来源：三个本质类

角色在任意时刻的能力 = `f(L0, 熟练度, 当前生效词缀集)`。其他所有"加成来源"都归到这三类之一：

| 类 | 颗粒度 | 性质 | 包含什么 |
|---|---|---|---|
| **L0 属性** | 跨技能（角色级） | 永久 | 本文档的主题，7 维：力量 / 精神 / 生命 / 法力 / 专注 / 意志 / 体力（见 §4） |
| **技能熟练度** | 单技能 | 永久（用进废退） | 该技能的基础参数 + 领悟新技能的前置 |
| **词缀** | 任意 | 永久 / 临时 / 条件 | 装备词缀 / buff / debuff / 套装 / 环境 / 难度——**一套 modifier 数据结构通吃** |

**没有独立的"AI 配置"调节层**：AI 决定"用什么招、打谁、何时撤"，纯行为，不直接给数值；它**间接**影响熟练度（哪些技能用得多）。

**没有独立的"天赋分支"**：被领悟系统吃掉（见 [doc/ideas.md](./ideas.md)）。

### L0 vs 熟练度的分工标准

判断一个参数归 L0 还是熟练度（多数情况两者都参与，但角色不同）：

**标准 0：能上 L0 的必须是"跨 build 都有意义的取舍"**。
若某项让所有 build 都必加（HP / 移速 / 暴击率），它对决策性是负贡献——走装备词缀承担（提供差异化分配机会）。见 §4.2。

**标准 1：跨技能共性 → L0；单技能特性 → 熟练度。**
问"这个参数变了，所有同类技能都该跟着变吗？"。是 → L0；否 → 熟练度。
- 物伤 / 法伤 / HP / MP / 命中闪避 / 意志 / 体力 = 跨技能 → **L0 管**（即本文 7 维）
- CD / 咏唱 / duration / area / tick / max_targets / cost / projectile_speed = 单技能 → **熟练度管**（+ 词缀微调）

**标准 2：熟练度 = 基础值，L0 = 乘数。**
```
final = base(熟练度) × (1 + L0_bonus) × (1 + 词缀_bonus) × condition_mul
```
熟练度决定"这一招本身有多猛"，L0 决定"这个角色当某流派有多牛"。两者乘法配合，不冲突。

**标准 3：曲线形态不同。**
- 熟练度：**线性永久 / 多项式无上限**，跟 L0 同样的 idle scaling 哲学。用进废退获经验值升级，但**等级无封顶**——保证装备 +技能等级永远生效，玩家"练满之后做什么"的问题不存在。
- L0：**线性永久**（呼应 idle 数值膨胀）
- 派生具体形态按 §1 类型分别处理：跨角色对抗派生 → 线性；非对抗派生（如召唤物数量）→ log 增长。
